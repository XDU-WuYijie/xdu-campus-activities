# 新前端迁移计划

## 1. 文档用途

本文档是 `frontend/` React 前端迁移的唯一进度清单，用于跨会话持续推进、确认完成状态和记录验收结果。

状态规则：

- `[ ]`：尚未完成，不得因为只创建文件或写完部分代码而勾选。
- `[x]`：实现、验证和文档同步均已完成。
- 每次只推进“当前目标”中的任务；完成一项后立即勾选并补充验证记录。
- 新会话开始前必须先读取本文档，确认当前目标和最后一次验证记录。
- 若实现范围或接口契约发生变化，先更新本文档和《功能模块设计》，再继续编码。

## 2. 总体目标

在不改变现有 Spring Boot 接口行为的前提下，将 `legacy-frontend/` 中的 Vue 2 静态页面迁移为独立的 React + TypeScript 单页应用。

完成后的前端应满足：

- 普通用户、活动负责人、平台管理员三类角色的现有功能全部可用。
- 使用 React Router 管理页面层级和返回关系。
- 使用类型化 API 层统一处理响应、鉴权、错误和上传。
- 使用 TanStack Query 管理服务端状态、分页和缓存失效。
- 使用 Ant Design Mobile 提供移动端基础控件。
- 保留项目既有校园移动端视觉，不直接套用默认组件主题。
- 通知和报名结果 WebSocket 支持心跳、重连和生命周期清理。
- 所有 Java `Long` 类型 ID 在前端保持为 `string`。
- 迁移期间旧前端持续可访问，最终切换前完成新旧功能对照验收。

### 3.2 接口约束

- 浏览器统一请求同源 `/api` 和 `/api/ws`。
- HTTP 代理移除 `/api` 后转发到 Spring Boot。
- 请求头使用 `authentication: <token>`。
- HTTP 响应统一按 `{ success, errorMsg, data, total }` 解包。
- `success: false` 即使 HTTP 状态为 200，也按业务错误处理。
- 上传请求使用 30 秒超时，普通请求默认使用 2 秒超时。
- WebSocket 地址：
  - `/api/ws/notification?token=...`
  - `/api/ws/activity-registration?token=...`
- 前端权限显隐以 `/user/me` 返回的 `roleCodes` 和 `permissions` 为准。
- 前端权限守卫只改善体验，后端仍是最终权限边界。

## 5. 完成定义

每个迁移任务只有同时满足以下条件才可标记为 `[x]`：

1. 页面或基础能力已经实现，不依赖旧页面脚本运行。
2. TypeScript 无错误，`npm run build` 和 `npm run lint` 通过。
3. 正常态、加载态、空态、错误态和无权限状态均有明确处理。
4. 涉及接口时，已验证请求参数、响应解包和错误提示。
5. 涉及角色时，已验证普通用户、活动负责人和平台管理员边界。
6. 涉及导航时，已验证直接访问、前进、后退和刷新。
7. 涉及移动端页面时，已检查窄屏和桌面居中布局，无溢出遮挡。
8. 已在本文档记录验证结果，并同步《工程进展》。
